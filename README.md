# AI Agent 101 —— 全栈工程师训练营

> AI Agent 101 你的全栈 AI Agent 的起点班, 从现在开始付出 101 分的努力

这个项目的起因是： 经常在朋友圈看到各种 AI Agent 全栈工程师训练营 的广告， 打开看一下还都不便宜，看一下课程规划其实都差不多，而且新的 Agent 热点包含的也比较少，所以我就干脆把这些训练营的数据爬了下来， 结合 2026 年最新 AI 行业趋势（A2A 协议、Agent FinOps、合规治理、AI Coding Agent 等）重新规划了一个大纲， 然后使用 GLM 5.2、GPT-5.6系列、 claude-opus-4.8、claude-fable-5 这些主流模型一起就这份大纲输出了一个循序渐进、可以持续跟进学习的详细课程讲义， 并且讲义中每章节都配了完整的代码实现。

下面是课程的介绍：

本课程面向已经具备基础开发能力的后端、全栈或平台工程师。应至少掌握：

- Python 基础、异步编程和面向对象设计；
- HTTP API、FastAPI 或同类 Web 框架；
- SQL、PostgreSQL 或同类关系型数据库；
- Git、单元测试、Docker 和命令行开发；
- 基础前端开发能力，能够阅读 TypeScript/React 代码。

整套课程围绕同一个持续演进的项目**Agent Engineering Platform**（`agent-platform/`）展开：

每一章只增加少量能力，最终交付可部署、可评测、可治理的全栈 Agent 平台。

1. [第一章]()让平台能够稳定调用模型，并通过网页流式返回结果。
2. 第二章让平台能够安全地发现和调用工具。
3. 第三章让平台能够执行多步任务、暂停、恢复和修改代码仓库。
4. 第四章让平台能够检索代码和文档，并管理项目记忆。
5. 第五章让多个 Agent 分工协作。
6. 第六章让你能用数据证明 Agent 是否变好了。
7. 第七章让平台具备部署、监控、成本控制和回滚能力。
8. 第八章让平台具备身份、权限、审计、脱敏和人工监督能力。
9. 第九章把平台包装成一个真正可使用的全栈产品。

每章结束时，项目都应该能运行；下一章不是推倒重来，而是在上一章的代码和数据上增加能力。

## 你将学到什么

- 稳定接入模型服务：结构化输出、流式响应、错误边界
- 安全调用工具：Tool Registry、权限、审计与 MCP
- 长程任务编排：Agent Loop、Checkpoint、Sandbox、Codebase Agent
- 上下文与检索：Context Budget、Memory、Codebase RAG
- 多 Agent 协作：Supervisor、Skill，以及 A2A 选修
- 工程闭环：Golden Tasks、Eval、Trace、FinOps、合规治理

## 主线技术栈 

为了让初学者不被过多工具分散注意力，课程使用一条主线技术栈。其他工具只做对比或选修实验。

| 领域 | 主线选择 | 使用目的 |
|------|----------|----------|
| 后端 | Python 3.12、FastAPI、Pydantic v2 | API、数据校验和服务编排 |
| 模型调用 | OpenAI-compatible Provider 抽象 | 统一接入云端或本地模型 |
| 数据库 | PostgreSQL | 用户、任务、工具、评测和审计数据 |
| 缓存/队列 | Redis | 会话、短期状态、事件和限流 |
| 检索 | PostgreSQL + pgvector 或 Qdrant 二选一 | 向量检索和项目知识库 |
| Agent 编排 | 先手写最小 Loop，后使用 LangGraph 对照 | 先理解原理，再学习框架 |
| 前端 | React/Next.js、TypeScript | 对话、任务、审批、Trace 和 Dashboard |
| 前端测试 | Playwright | 验证真实用户流程 |
| 后端测试 | pytest、httpx | 单元测试、接口测试和 Agent 回归测试 |
| 部署 | Docker Compose | 本地和教学环境的一键启动 |

课程不会要求你同时熟练掌握所有主线工具。每次引入一个工具，都先解释它解决什么问题、没有它会怎样、为什么现在引入。

## 需要补齐的盲点

很多 Agent 课程默认学员已经懂这些内容，导致初学者在后面反复卡住。本课程明确补齐以下盲点：

- **HTTP 不等于模型调用**：模型调用也是网络请求，仍然会超时、限流、断开和返回非法数据。
- **模型输出不等于程序结果**：自然语言必须经过 Schema 校验，才能进入业务代码。
- **工具调用不是函数调用的语法糖**：工具有权限、风险、审计、超时和副作用。
- **Agent 不是一个更长的 Prompt**：Agent 是模型、工具、状态、上下文和执行环境组成的循环系统。
- **上下文不是越长越好**：无关信息会污染模型决策，也会增加延迟和成本。
- **RAG 不是上传文件后自动变聪明**：解析、切分、召回、重排、引用和评估每一步都可能出错。
- **多 Agent 不等于多调用几次模型**：协作需要任务边界、上下文边界、权限边界和结果协议。
- **Demo 成功不等于系统可靠**：必须保存任务集、轨迹、失败样本和版本对比结果。
- **部署成功不等于上线**：上线还需要密钥、租户、审计、告警、成本、灰度和回滚。
- **前端不是最后加一层页面**：Agent 的暂停、审批、失败和恢复都必须在 UI 中可理解、可操作。
