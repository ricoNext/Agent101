# 第 5 课：部署、演示与答辩

> 所属章节：[第 9 章：完成一个可展示的全栈 Agent 产品](./index.md)  
> 上一课：[第 4 课：做一次真实的质量改进](./lesson-56-quality-improvement.md)

提交物：

- `README.md`：安装、配置、启动和测试；
- `docs/architecture.md`：组件和数据流；
- `docs/runbook.md`：部署、排错、回滚和 Kill Switch；
- `docs/eval-report.md`：任务集和改进前后数据；
- `docs/risk-assessment.md`：权限、数据和审批设计；
- 5-10 分钟演示视频；
- Docker Compose 启动记录；
- 一次成功、一失败、一次审批的 Trace。

答辩按下面结构：

1. 场景和用户痛点；
2. 主流程演示；
3. 失败与恢复演示；
4. 评测和成本数据；
5. 权限、审计和风险边界；
6. 下一步会如何扩展。

### 第九章最终验收

| 维度 | 最低要求 |
|------|----------|
| 主流程 | 一个真实任务端到端成功 |
| 可靠性 | 有状态、取消、恢复和错误处理 |
| 安全 | 写操作审批、Scope、审计和 Kill Switch |
| 质量 | 至少 20 个 Golden Tasks 和一次版本对比 |
| 全栈 | 可操作的任务页、证据、审批和运维信息 |
| 部署 | 干净环境可通过 Docker Compose 启动 |
| 表达 | README、架构、Runbook、Eval 报告和演示 |

课程结束后继续积累的不是框架清单，而是任务集、失败样本、Trace、权限边界、用户反馈和质量/成本数据。这些资产会让你的 Agent 工程能力持续增长。
