# 第 4 课：做一次真实的质量改进

> 所属章节：[第 9 章：完成一个可展示的全栈 Agent 产品](./index.md)  
> 上一课：[第 3 课：完成全栈用户流程](./lesson-55-fullstack-user-flow.md)  
> 下一课：[第 5 课：部署、演示与答辩](./lesson-57-deploy-demo-defense.md)

选择一个失败样本，按以下顺序改进：

1. 保存当前基线指标；
2. 从 Trace 确认失败层；
3. 只修改一个假设相关因素，例如检索过滤或工具描述；
4. 重跑全部 Golden Tasks；
5. 记录成功率、引用、P95、成本和安全指标；
6. 若有退化，回滚或解释权衡。

作品集中最有价值的部分不是“用了什么框架”，而是“如何用数据修复一个真实失败”。
